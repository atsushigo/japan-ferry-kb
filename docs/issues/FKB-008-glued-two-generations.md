# FKB-008：回答中出現兩段輸出拼接（截斷的前半＋完整的後半）

| Field | Value |
|---|---|
| Type / Priority / Status | Bug / High / Open（失敗重試的猜測已被否定；成因未知） |
| Component | chatbot-flow、model |
| Found in | chat-001（42 次請求中 3 次）；LLM 節點「失敗時重試」疑似為開啟狀態 |
| Reported | 2026-11-21 JST |
| Related | FKB-007、FKB-001 |

## Description
同一則回答裡，前一段在句子中間被截斷，後面緊接一整份新的回答：

- A1 #1：「…內側房 INSIDE CABIN」後面直接接「大阪到釜山（パンスターミラクル号）的單程票價依艙等而定…」。此次前半段含錯誤金額（FKB-007）。
- A1 #3：「…稅金與燃油附加費」後面直接接「大阪到釜山（パンスターミラクル号）的單程票價依房型而定…」。
- A3 #2：「…扣 30%」後面直接接另一份完整的取消規定。
3 次都發生在長回答（表格／清單）。使用者會看到重複且不完整的內容。

## Test of the retry hypothesis（chat-002，2026-11-21 JST，重試已關閉）
A1、A3 各重跑 10 次（20 次請求）：仍出現 1 次拼接（A3 #4，前半在「出航 9～7 日前：15%」被截斷，後面緊接一份新的完整回答）。結論：**關閉重試後拼接沒有消失，「失敗重試造成拼接」不成立（至少不是唯一原因）。**
合併 chat-001（3 次）與 chat-002（1 次）：A1、A3 共 26 次請求中 4 次拼接，全部是長回答（表格或多層清單）；其他題的 36 次請求沒有發現。樣本小，只能當線索。

## Root cause（目前未知；以下為尚未驗證的猜測）
- ~~失敗重試保留半截輸出~~：已被 chat-002 否定（見上）。
- 剩下的可能：模型生成長回答時自己重新開始；或 Dify 的 LLM 節點／回覆節點／串流處理把兩段輸出接在一起。目前無法區分。
- 區分方法：到 Dify「日誌」找 chat-002 中使用者 `eval-runner` 的 A3 #4 對話，看 LLM 節點的原始輸出是否已含兩段（模型的問題），還是只有回覆節點才出現（Dify 的問題）。

## Resolution / Workaround（提案）
1. ~~關閉重試並重跑~~：已做（chat-002），沒有解決。
2. 看 Dify 日誌中該次對話的 LLM 節點原始輸出，判斷是模型還是 Dify。
3. 用 Gemini 3.8 Flash 對照（FKB-006）；若只在 Flash-Lite 出現，歸因於模型。
4. 暫時的緩解：評分腳本的 glued_output 已能標出；產品層面可考慮縮短長回答（例如規定取消規則只列重點）。

## Verification
未完成。`glued_output` 是啟發式（開頭四個字在句中緊黏重現），在 chat-001 抓到的 3 筆都經人工逐筆確認屬實；它曾把「結尾句放在來源行之前」誤判為拼接，已修正。

## Lessons learned
- 猜測要用實驗檢驗：這次關掉重試的實驗否定了我們最初的解釋，如果當初直接寫成「已知成因」就是錯的。
- 重試設定要連同測試結果一起記錄（chat-002 的 config.json note 有記）。
