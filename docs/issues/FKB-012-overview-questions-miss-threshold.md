## Description
使用者問「大阪からどこまでいけますか」（從大阪可以去到哪裡），機器人回固定的「知識庫目前沒有這項資料」三語訊息。知識庫其實有答案（釜山、上海兩條航線），但這種概括性問題與任何一個段落都不夠像，分數沒有過閾值 0.71，走到 ELSE 分支。

## Root cause（Suspected，未驗證）
- 知識文件是「一段一個主題」，沒有「有哪些航線」的總覽段落，概括性問題沒有對應的段落可以命中。
- 閾值 0.71 是為了擋庫外題（安全區間只有 0.017 寬），代價是概括、口語的問法也容易被擋。
- 需要用 `run_recall.py` 對這題實測分數才能確認（尚未做）。

**校準集回歸（run-008，26 題，門檻關閉）**：庫外題最高分仍是 0.6975（Q20 福岡到釜山），相關段落最低分仍是 0.7147（Q6），**安全區間沒有變**；有預期段落的 15 題 hit rate 1.0、MRR 1.0；庫外題沒有任何一題 ≥ 0.71。新段落會出現在許多不相關題的前幾名（例如 Q1 第 3 名 0.7895），不影響門檻判斷，但會多給 LLM 一個總覽段落當上下文。庫外題中總覽段落的分數 0.61–0.69，都低於 0.71；Q20 的總覽段落為 0.6887，距離 0.71 的餘裕仍只有約 0.02。

**回答層（chat-008，v4，A30–A35 各 3 次）**：A30–A34 共 15 次 **15/15 同時列出釜山、上海並說明上海暫停**；其中 3 次暫停狀態沒有在前 120 字（A31 #2、A33 #1、A34 #3），違反規則 3 的「第一句先說明」；日英題仍以中文回答（FKB-009，已延後）。**A35（原本被擋的 Q27）3/3 仍回「知識庫沒有這項資料」。**

**為什麼不繼續調 Q27**：它是最模糊的問法（どこまで＝能去多遠），0.6983 與庫外題最高分 0.6975 只差 0.0008，不可能靠調閾值解決；若為了它把總覽段落改成含「大阪からどこまで」的字句，是為單一測試題過度擬合。留出題 Q31、Q32 已證明一般的日文概括問法能命中。

## Resolution（提案，未驗證）
1. **介面層**：在 Dify「功能」開啟「對話開場白」並設定開場問題按鈕（用已測過會命中的題目，三語各幾題），降低使用者問到庫外或太概括問題的機率。
2. **資料層**（檔案已備：`knowledge/overview-routes.md`，尚未上傳 Dify）：新增一個「【總覽】從關西出發的國際航線」段落（航線、營運公司、目前狀態），並加入概括性問題的測試題；改完要重跑召回測試，確認閾值區間沒有被破壞。
3. **流程層（下一步，使用者在 Dify 改「直接回覆 2」節點）**：ELSE 分支的訊息可以改成帶引導：列出可以問的主題，而不只是「沒有資料」。

## Verification
- 開場問題按鈕：每個按鈕的問題都要在 `test-conversations.csv` 有對應題並通過。
- 總覽段落：新增概括性測試題（含日文「大阪からどこまでいけますか」），召回測試必須命中，且庫外題仍然全部被擋（0.71 不變）。

## Lessons learned
- 使用者不知道可以問什麼，是產品問題，不只是檢索問題；好的開場問題同時是引導和測試集。
